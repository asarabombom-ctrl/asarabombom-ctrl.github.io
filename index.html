L0: Апаратна діагностика та Provisioning L0: Hardware Diagnostics & Provisioning

Повний алгоритм дій IT Support при надходженні проблемної робочої станції.

1. Базова перевірка POST (Power-On Self-Test)

Якщо ПК не стартує (немає зображення), перевіряємо Beep-коди материнської плати або POST-карту. Очищення CMOS (замикання пінів CLRTC) — перший крок при збоях налаштувань BIOS/UEFI.

2. Тестування ОЗП (RAM)

При синіх екранах (BSOD) `MEMORY_MANAGEMENT`: Завантаження з USB у WinPE → запуск MemTest86. Тест повинен пройти мінімум 2 проходи (Passes) без жодної червоної помилки.

3. Стрес-тест CPU та живлення

Використовуємо OCCT або AIDA64 System Stability Test.

Критерії пройденого тесту:
1. Температура CPU не перевищує 85°C (залежить від Tjunction).
2. Графік CPU Throttling (тротлінг) суворо 0%.
3. Напруга по лініях 12V, 5V, 3.3V не просідає більше ніж на 5%.

L1: Робоче середовище Windows Server L1: Windows Server Environment

Конспект з налаштування доменної інфраструктури та базової автоматизації.

1. Ієрархія Active Directory (OU Design)

Ніколи не звалюйте всіх користувачів у контейнер `Users`. Створюйте Organizational Units (OU) за відділами (напр. `OU=Sales, DC=enterprise, DC=com`). Це дозволяє делегувати права (Delegation of Control) та прив'язувати різні GPO.

2. Права NTFS vs Share Permissions

Правило: Share Permissions завжди ставимо "Everyone -> Full Control". Увесь реальний захист та обмеження налаштовуються виключно на вкладці Security (NTFS). Забороняюче правило (Deny) завжди має вищий пріоритет.

3. PowerShell: Корисні сніпети

# Знайти процеси, які споживають більше 500МБ ОЗП, та вбити їх
Get-Process | Where-Object {$_.WorkingSet -gt 500MB} | Stop-Process -Force

# Масове створення користувачів AD з CSV файлу
Import-Csv -Path "C:\users.csv" | ForEach-Object {
  New-ADUser -Name $_.Name -SamAccountName $_.Username -Path "OU=Users,DC=domain,DC=local"
}

L2: Архітектура Linux систем L2: Linux Systems Architecture

Ключові команди та налаштування безпеки для серверів на базі Debian/Arch.

1. Безпека SSH (Hardening)

Файл конфігурації: /etc/ssh/sshd_config. Після зміни завжди systemctl restart sshd.

# Базові правила безпеки
PermitRootLogin no # Заборонити прямий вхід під root
PasswordAuthentication no # Вхід виключно по RSA/Ed25519 ключах
Port 2202 # Змінити стандартний порт для відсікання базових сканерів

2. Управління логічними томами (LVM)

Алгоритм розширення диска без перезавантаження:

1. pvcreate /dev/sdb1 # Створити фізичний том
2. vgextend vg_main /dev/sdb1 # Додати до групи томів
3. lvextend -l +100%FREE /dev/vg_main/lv_root # Розширити логічний том
4. resize2fs /dev/vg_main/lv_root # Розширити файлову систему (ext4)

L3: Мережева Інфраструктура (MikroTik) L3: Network Infrastructure (MikroTik)

Конспект з налаштування маршрутизації, VLAN та NAT.

1. Базовий NAT (Маскарадинг)

Щоб локальна мережа отримала доступ до інтернету, потрібно налаштувати правило srcnat.

# RouterOS CLI: Налаштування NAT для виходу в інтернет через ether1
/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade

2. Ізоляція мереж через VLAN (802.1Q)

Створюємо VLAN для гостьової мережі, щоб відокремити її від корпоративної (Trunk порт на ether2).

/interface vlan add name=VLAN20_Guest vlan-id=20 interface=ether2
/ip address add address=192.168.20.1/24 interface=VLAN20_Guest
/ip dhcp-server setup # Далі слідувати майстру налаштування для VLAN20

L4: Віртуалізація та Docker L4: Virtualization & Docker

Декларативне розгортання сервісів за допомогою Docker Compose.

1. Типовий docker-compose.yml (Nginx + PHP)

Приклад конфігурації для підняття веб-стеку з прокиданням портів та постійним сховищем (Volumes).

version: '3.8'
services:
  web:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./html:/usr/share/nginx/html
    restart: always

2. Очищення системи Docker

Команди для звільнення місця від старих образів та зупинених контейнерів.

docker system prune -a --volumes # Видаляє ВСІ невикористані дані
docker stop $(docker ps -aq) # Зупинити всі поточні контейнери

L6: Автоматизація (Bash Scripting) L6: Automation (Bash Scripting)

Написання скриптів для резервного копіювання за розкладом.

1. Скрипт бекапу директорії (rsync)

#!/bin/bash
SOURCE="/var/www/html"
DEST="/mnt/backup/web_$(date +%F)"

# Синхронізація з видаленням файлів, яких вже немає в джерелі
rsync -av --delete $SOURCE $DEST
echo "Backup completed on $(date)" >> /var/log/backup.log

2. Додавання в Cron

Виконуємо crontab -e та додаємо завдання для запуску о 02:00 ночі щодня.

0 2 * * * /opt/scripts/backup.sh

L7: Кібербезпека (Hardening) L7: Cybersecurity (Hardening)

Базовий захист сервера від мережевих атак.

1. Налаштування UFW (Uncomplicated Firewall)

Політика "Заборонити все, дозволити лише потрібне" (Default Deny).

ufw default deny incoming
ufw default allow outgoing
ufw allow 2202/tcp # Дозвіл для нестандартного порту SSH
ufw allow 80,443/tcp # Дозвіл для веб-трафіку
ufw enable

2. Захист від Bruteforce (Fail2ban)

Створюємо локальний конфіг /etc/fail2ban/jail.local для блокування IP після 3 невдалих спроб входу.

[sshd]
enabled = true
port = 2202
maxretry = 3
bantime = 3600 # Блокування на 1 годину
